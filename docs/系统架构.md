# 系统架构与操作边界

## 数据与交接

1. Mac 研究器从合法 IPA 和本地媒体提取证据，写入 `static.json`、`media.json` 和中文报告。SHA-256 保留完整值。媒体 ID 由原文件名和摘要前缀组成，新增其他文件不会改动已有 ID。
2. 静态检查读取主程序 Mach-O 加载命令、动态依赖、签名能力、可读隐私清单、URL 声明、内嵌组件配置和部分本地化文案。加密标记缺失或工具不可用时保留未知状态。报告中的资源仅能支持静态线索，SDK 是否在特定流程调用及服务端规则需要行为证据。
3. FFmpeg 处理全片，检测换场并每 15 秒补帧，报告实际时间。Vision 在本机识别。观察仍需核对前后画面，关键操作可留独立截图。
4. 研究器从核对过的证据和设计生成 PRD。可选 Markdown 章节包含页面与导航、用户流程、数据与状态、业务规则、异常、非目标、优先级与里程碑。功能证据使用 `basis` 字段。Kandev Spec 根据当前实现自行拆分开发任务。
5. `tools/kandev_intake.py` 向 Kandev 提交范围、验收、基线、报告路径及可选的可分享证据摘要。Kandev 管理工作树、会话、原生计划与状态。Gemini 文档步骤通过已登录的 Antigravity 纯文本调用生成，操作员保存产物。
6. Gemini 的初稿交给独立 Claude 架构会话。Gemini 依据架构写开发规格。Codex 同时读取原生计划和原创文档，在独立工作树开发并验收。Claude 在新会话审查，Codex 读取审查反馈并执行至多一轮修复，Claude 独立复核。
7. 最终文档仍由 Gemini 依据真实差异和测试编写。Draft PR 步骤核对 Claude 已审的代码与随后只改 Markdown 的提交。原生 CI 步骤按精确 HEAD 验收，失败停留并记录，绿灯后等待人工决定是否合并。

## 停止与恢复

在 Kandev 任务内停止当前会话的运行，再从该步骤向会话补充信息并继续。停止没有明确完成信号的运行不会推动下一步。可在看板取消整项任务。若取消的任务仍占用 WIP 名额，归档后 Kandev 会放行排队任务。若修复失败或 CI 红灯，先检查工作树和日志，确认本次已提交产物后再决定从当前步骤继续或移回 Work。取消任务后，已经推送的分支和 Draft PR 需要在 GitHub 单独处理。

## Mac 与未来 VPS

Mac 运行 IPA 的 Apple 元数据读取、Vision、Xcode 编译、签名、模拟器与实机。XCTest 的 Xcode 共享方案可以在 Mac 运行，GitHub macOS CI 已配置同一方案。配对实机仍需设备所有者信任本机开发证书。

如以后采用 Ubuntu VPS，将 Kandev SQLite、仓库与可分享研究产物分开迁移。VPS 可承载编排和非 iOS 验证任务。先验证 Kandev SSH 执行器可在 Mac 上稳定保留同一个任务工作树，再让需要 Xcode 的任务在该执行器运行。暂时保留 GitHub macOS CI 作远程验收。手机访问可在 Tailscale 内网接入，保留 Kandev 回环监听并启用认证和访问控制。VPS、SSH 执行器和手机端尚未在此次 Mac 验收中部署。
