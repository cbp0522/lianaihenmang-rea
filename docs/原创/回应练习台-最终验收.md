## 2. 已实现功能（以代码为准）

### 2.1 领域核心层（`apps/ReplyWorkbench/Core/`，仅依赖 `Foundation`）

- **沟通意图与原创离线模板**：
  - `ReplyIntent` 定义 4 种沟通意图，各自附带一句说明，并对应 `ReplyTemplates` 中的 4 条原创离线模板：
    - `decline`（婉拒）：说明做不到，同时保留关系
    - `soften`（缓和）：先降温，再谈事情
    - `confirm`（确认）：把关键信息说清楚
    - `followUp`（跟进）：不施压地询问进展
- **草稿会话状态机（`DraftSession`）**：
  - 维护 `selectedIntent`、`draft`、`pendingIntent`、`copyStatus`（`idle` / `copied` / `blankRejected`）及 `lastCopiedText`。
  - **空白草稿判定**：以 `whitespacesAndNewlines` 排除零宽空格 `U+200B` 后的字符集对 `draft` 进行修剪，结果为空即判定为空白。由于 iOS 26.2 运行时将 `U+200B` 纳入 `whitespacesAndNewlines`，实现中显式排除以保持产品定义的非空白语义。
  - **可复制条件**：`canCopy` 仅在已选意图且草稿非空白时为真。
  - **受保护编辑与切换保护**：
    - 当已选意图、草稿非空白、且内容与当前意图模板 UTF-8 不相等时，视为存在受保护编辑。
    - `select(_:)`：存在受保护编辑时返回 `needsConfirmation` 并记录待定意图（含再次点击当前意图）；选择同一意图且草稿非空白（无受保护编辑）时返回 `unchanged`；其余情况返回 `applied` 并填入对应模板。
    - `confirmReplacement()`：应用待定意图并替换为新模板，清空待定状态。
    - `cancelReplacement()`：仅清空待定意图，保留当前意图与草稿内容。
  - **编辑更新**：`updateDraft(_:)` 在未选择意图时直接忽略；当草稿内容与 `lastCopiedText` 不一致时，将 `copyStatus` 重置为 `idle`。

### 2.2 剪贴板写入与隐私边界（`apps/ReplyWorkbench/App/`）

- `WorkbenchModel.copy()` 仅在用户主动点按复制按钮时调用：
  - 草稿为空白时不调用写入器，并将状态设为 `blankRejected`。
  - 草稿有效时按原样（**不做 trim**）写入，并将状态设为 `copied`；每次点按均执行写入。
- `apps/ReplyWorkbench/App/SystemClipboardWriter.swift` 是本应用源码（`App`、`Core`、`Tests`、`UITests`）中唯一引用 `UIPasteboard` 的文件，仅包含一行写入语句，不执行任何读取操作。
- 草稿仅保存在内存中，不落盘、不同步，进程结束后即清空。

### 2.3 界面交互与可访问性

- **空态 E0（未选意图）**：显示「先选择一种沟通意图，再生成离线草稿」，不显示编辑器，复制按钮禁用。
- **空态 E1（草稿空白）**：显示「草稿为空，输入内容后才能复制」，复制按钮禁用。
- **复制反馈**：复制成功后在布局内固定状态行显示「已复制到剪贴板」（不使用浮层或 Toast）。
- **替换确认框**：提供「替换为新模板」与「保留当前草稿」两个按钮。因 iOS 26.2 模拟器会隐藏 `cancel` 角色按钮，「保留当前草稿」使用普通按钮显式执行取消替换。
- **可访问性标识**：固定声明 `intent.decline`、`intent.soften`、`intent.confirm`、`intent.followUp`、`emptyStateHint`、`draftEditor`、`blankHint`、`copyDraft`、`copyStatus`。

### 2.4 最小权限静态检查与 CI 配置

- **静态检查脚本（`apps/ReplyWorkbench/check.sh`，由 `tools/check.sh` 调用）**：

  - 禁止 `App/` 与 `Core/` 出现 `Network`、`StoreKit`、`AuthenticationServices`、`URLSession`、`UserDefaults`、`AppStorage`、`SceneStorage`、`FileManager`、`FileHandle`、`SwiftData`、`CoreData`、`Keychain`、`SecItem*`、`PasteButton`、`write(to:)`。
  - 禁止工程中出现任何 `NS*UsageDescription` 与 entitlements 配置。
- **CI 流程（`.github/workflows/checks.yml`）**：

## 6. 复审发现与修正

### 6.1 已关闭问题：R-01（UI 测试确认框动画同步竞态）

- **背景**：在初始实现提交 `3e42583` 后的独立审查中，UI 测试在本机连续 2/2 失败（退出码 65）。经对照实验确认，产品逻辑本身正确，失败原因在于 UI 测试在确认框关闭动画期间立即执行断言。
- **修复提交**：`28ced2b3f628a4b3c5c951827a0e68d5fe98a283`（仅修改 `UITests`，未改动产品代码）。
- **修正方式**：点按确认框按钮后，先通过 `waitForNonExistence` 等待确认按钮消失，再使用 `XCTNSPredicateExpectation` 等待目标意图选中状态与草稿值更新（超时上限 5 秒，不使用固定 `sleep`）。
- **复核结论**：多轮本地测试、独立复核及交付前复验均通过（失败 0 次），**R-01 已关闭**。

### 6.2 已知非阻塞改进建议

- UI 测试辅助方法 `focusAtEnd` 目前通过归一化坐标 `(0.85, 0.7)` 点击将光标定位至编辑器末尾；若未来调整模板长度或字号，该坐标定位可能失效。后续建议改用方向键移动光标，或改为更稳健的包含断言。
