## 2. 首发切片的交互设计

### 2.1 单屏布局（自上而下）

1. 标题「回应练习台」（`.largeTitle`，带 header trait）。
2. **意图选择区**：四个可选卡片或按钮，竖向排列；在常规字号下可用两列网格。每项显示名称和一句说明。选中项用 `.borderedProminent` 加对勾标记，并带 `.isSelected` 可访问性 trait。
3. **草稿区**：
   - 未选择意图时（空态 E0），不显示编辑器，改为显示引导文字「先选择一种沟通意图，再生成离线草稿」。
   - 已选择意图时，显示 `TextEditor`，最小高度约 160pt，内容可滚动。编辑器下方显示字数。
4. **操作区**：「复制草稿」主按钮，以及按钮下方的状态行。状态行是固定在布局里的一行文字，不使用浮层或 Toast，因此重复点击不会叠加遮挡（F05）。
5. 页面整体放在 `ScrollView` 内。在 Dynamic Type 的辅助功能字号下，意图区改为单列，按钮不被截断（F06）。

### 2.2 意图与原创模板

| `ReplyIntent` | 显示名 | 说明 | 原创模板（`ReplyTemplates`） |
|---|---|---|---|
| `.decline` | 婉拒 | 说明做不到，同时保留关系 | 谢谢你想到我。这次我确实安排不开，先不答应了，免得到时做不好耽误你。之后有合适的机会，我们再约。 |
| `.soften` | 缓和 | 先降温，再谈事情 | 刚才我的语气有点急，抱歉。我不是在怪你，只是想把这件事处理好。我们都缓一缓，晚点再好好聊，可以吗？ |
| `.confirm` | 确认 | 把关键信息说清楚 | 我再确认一下：我们约定的是【时间】在【地点】，由我负责【事项】。如果有出入请告诉我，没有的话就按这个来。 |
| `.followUp` | 跟进 | 不施压地询问进展 | 想跟你确认一下之前聊的那件事，现在进展怎么样了？不着急，你方便时回我一句就好，有需要我配合的也可以直接说。 |

- 上表模板文字是本项目原创内容，Codex 按原文写入 `ReplyTemplates.swift`。测试用 `ReplyTemplates.text(for:)` 比较，不复制字面量。
- `ReplyIntent` 遵循 `CaseIterable`。界面顺序与上表一致。

### 2.3 空白与空态语义（规范定义）

- **空白草稿**：用 Foundation 的 `whitespacesAndNewlines` 去除 `U+200B` 后作为修剪字符集，再判断结果是否为空。覆盖空字符串、空格、`\t`、`\n`、`\r\n`、全角空格 `U+3000`。iOS 26.2 的 Foundation 将零宽空格 `U+200B` 纳入原字符集，因此显式排除以保留产品要求的非空白语义，由单测覆盖。
- **E0 未选择意图**：`selectedIntent == nil`。不显示编辑器，复制按钮禁用，状态行为空。
- **E1 已选意图、草稿空白**：显示编辑器，复制按钮禁用，状态行显示「草稿为空，输入内容后才能复制」。
- **可复制**：`selectedIntent != nil && !isDraftBlank`。
- **复制内容**：按草稿原样写入，**不做 trim**，因此剪贴板与编辑器内容逐字一致（AC-01）。
- 防御：即使按钮可用状态和模型不同步，`copy()` 仍会先检查。草稿空白时不调用写入器，状态设为 `.blankRejected`（F01）。

## 3. 领域模型与状态机（`Core/`）

### 3.1 类型

```swift
enum ReplyIntent: String, CaseIterable, Identifiable, Sendable { case decline, soften, confirm, followUp }
enum ReplyTemplates { static func text(for intent: ReplyIntent) -> String }

enum CopyStatus: Equatable { case idle, copied, blankRejected }

enum SelectionOutcome: Equatable { case applied, unchanged, needsConfirmation }

struct DraftSession: Equatable {
    private(set) var selectedIntent: ReplyIntent?
    private(set) var draft: String
    private(set) var pendingIntent: ReplyIntent?
    private(set) var copyStatus: CopyStatus
    private(set) var lastCopiedText: String?

    var isDraftBlank: Bool
    var canCopy: Bool
    var hasProtectedEdits: Bool   // selectedIntent != nil && !isDraftBlank && draft != 模板

    mutating func select(_ intent: ReplyIntent) -> SelectionOutcome
    mutating func confirmReplacement()
    mutating func cancelReplacement()
    mutating func updateDraft(_ text: String)
    func copyPayload() -> String?            // 空白时返回 nil
    mutating func markCopied(_ text: String)
    mutating func markBlankRejected()
}

protocol ClipboardWriting { func write(_ text: String) }   // 只有写入，没有读取方法
```

`App/` 中的 `@MainActor final class WorkbenchModel: ObservableObject` 持有 `@Published var session` 和注入的 `ClipboardWriting`，并提供：

```swift
func copy() {
    guard let payload = session.copyPayload() else { session.markBlankRejected(); return }
    clipboard.write(payload)
    session.markCopied(payload)
}
```

### 3.2 迁移规则

| 当前状态 | 事件 | 结果 |
|---|---|---|
| E0 | `select(x)` | `selectedIntent=x`，`draft=模板(x)`，`copyStatus=.idle`，返回 `.applied` |
| 已选 a，草稿等于模板(a) | `select(a)` | 不变，返回 `.unchanged` |
| 已选 a，无受保护编辑（草稿等于模板，或为空白） | `select(b)` 或 `select(a)` | 直接替换为模板，`copyStatus=.idle`，返回 `.applied` |
| 已选 a，有受保护编辑 | `select(任意，含 a)` | `pendingIntent=该意图`，其余不变，返回 `.needsConfirmation` |
| 存在 pending | `confirmReplacement()` | `selectedIntent=pending`，`draft=模板(pending)`，清空 pending，`copyStatus=.idle` |
| 存在 pending | `cancelReplacement()` | 清空 pending，意图和草稿保持原样 |
| 任意已选 | `updateDraft(t)` | `draft=t`。若 `t != lastCopiedText`，`copyStatus` 回到 `.idle`；若 `t` 空白，界面显示 E1 提示 |
| 可复制 | `copy()` | 写入原样草稿，`copyStatus=.copied`，`lastCopiedText=draft`。重复点击会再次写入相同文本，状态仍为 `.copied`（F05，幂等） |
| 草稿空白 | `copy()` | 不写入，`copyStatus=.blankRejected` |

### 3.3 F03 决定说明

- 选择“确认”而不是静默保留或静默重置。理由：静默重置会丢失用户输入；静默保留会让意图高亮与草稿内容不一致。
- 再次点击当前意图，等同于“恢复该意图的模板”，同样受确认保护。这样不需要单独的“还原”按钮。
- 确认框使用 `.confirmationDialog`。标题「替换当前草稿？」，按钮「替换为新模板」（destructive）和「保留当前草稿」（普通按钮，显式取消替换）。iOS 26.2 的弹层会省略 cancel 角色的按钮，因此保留操作使用普通按钮。

## 5. 未来 Keyboard Extension（不在首发切片实现）

### 5.1 拆分

- 未来新增 Target `ReplyWorkbenchKeyboard`（扩展点 `com.apple.keyboard-service`）。主类 `KeyboardViewController: UIInputViewController` 用 `UIHostingController` 承载 SwiftUI 视图。
- 扩展只编译 `Core/` 和自身的 UI 文件，不链接 `App/`。领域规则保持一份。
- 扩展职责只有三项：列出意图 → 预览模板（扩展内只读）→ 用户点按「插入」后调用一次 `textDocumentProxy.insertText(_:)`。编辑长文本仍回到主应用。

### 5.2 生命周期与限制（平台资料，未实机验证的部分标“待验证”）

- 系统随时可能创建、销毁或重建控制器。扩展不保存长期状态，每次 `viewWillAppear` 都从模板（以及 §6 的只读共享配置）重新构建。
- 必须在 `needsInputModeSwitchKey == true` 时显示切换键盘按钮，并调用 `handleInputModeList(from:with:)`。
- 在安全文本框、电话号码键盘，以及通过 `application(_:shouldAllowExtensionPointIdentifier:)` 禁用第三方键盘的宿主中，系统会回退到原生键盘。扩展不做特殊处理。
- 扩展内存预算明显小于主应用，具体数值**待验证**。不加载大图，不常驻缓存。
- 扩展**不**读取剪贴板，**不**读取 `documentContextBeforeInput` 发往任何地方。首版扩展里 `RequestsOpenAccess = false`。

## 6. App Group 能力与降级（未来）

- 只有出现“用户自定义模板需要同步到键盘”这一需求时，才启用 App Group `group.org.iosresearch.ReplyWorkbench`。首发切片不声明该能力。
- **数据契约 v1**：容器内文件 `ReplyWorkbench/v1/preferences.json`。
  ```json
  { "schemaVersion": 1, "updatedAt": "ISO8601", "customTemplates": { "decline": "…" } }
  ```
  - 只有主应用写入，并使用原子写入；扩展只读。
  - 文件上限 64 KiB。不保存草稿正文、复制历史或任何对话内容。
- **降级顺序**（扩展读取时）：文件存在且版本为 1 → 使用自定义模板；文件缺失、解析失败、版本未知或超过上限 → 回退到内置 `ReplyTemplates`，并且不报错。
- **没有 Full Access 时**：按平台资料，系统会限制扩展的共享容器访问和网络访问，具体读写表现**待实机验证**（对应研究计划 O03）。本设计不要求扩展写入，读取失败也能完整使用内置模板，所以开关状态只影响是否显示自定义模板。扩展内提示「在主应用中编辑的模板暂不可用，已使用内置模板」，不引导用户开启 Full Access。

## 7. 未来自愿 AI 润色、提交与删除

- **接口**：
  ```swift
  protocol ReplyAssistClient {
      func suggest(_ request: AssistRequest) async throws -> AssistSuggestion
  }
  struct AssistRequest { let intent: ReplyIntent; let draft: String }
  ```
  默认实现 `OfflineTemplateAssist` 只返回模板，不联网。
- **调用位置**：只在主应用中调用，键盘扩展不联网。只有用户点按「请 AI 润色」时才调用。每次提交前弹出确认页，**原样显示将要发送的文字**。首次使用需要单独同意说明，用户可在设置中随时关闭。
- **提交内容**：只包含用户编辑区中的草稿和意图。不包含剪贴板、通讯录、截图、宿主输入框上下文或设备标识。
- **删除与保留**：
  - 本地默认不保存 AI 历史。如以后增加历史，提供逐条删除和「全部删除」，删除后立即从磁盘移除。
  - 服务端选型要求默认零保留。如果服务端必须暂存，每次请求返回 `submissionId`，主应用提供「删除我提交的内容」，按 ID 发起删除请求，不需要账号。删除失败时显示失败原因并保留重试入口。
- **回退**：超时（建议 10 秒）、离线或服务错误时，保留用户原草稿并显示错误原因，不自动替换文本。
- 引入网络后，再单独评审隐私清单和 App Store 隐私标签。

## 8. 验收条件（替代初稿 AC，对应 F01–F07）

- **AC-01 主路径**：选择任一意图后，编辑器内容等于对应模板；编辑后点击复制，写入器收到的文本与编辑器内容逐字相同。
- **AC-02 空白拒绝**：`""`、`"   "`、`"\n\t "`、`"\r\n"`、`"\u{3000}"` 均判定为空白，复制按钮禁用；直接调用 `copy()` 不触发写入，状态变为 `.blankRejected`。`"\u{200B}"` 的现状由单测记录。
- **AC-03 反馈**：复制成功后状态行显示「已复制到剪贴板」；修改草稿使内容与上次复制不同时，状态回到空；重复复制不叠加提示。
- **AC-04 最小权限**：App 不含 `NS*UsageDescription`，不含 entitlements，不导入 Network、StoreKit、AuthenticationServices，不使用 `URLSession`，不读取剪贴板，不持久化草稿。`apps/ReplyWorkbench/check.sh` 用 grep 强制检查：`UIPasteboard` 只允许出现在 `SystemClipboardWriter.swift`，且该文件只有赋值写入。
- **AC-05 既有资产**：节奏记录（`tests/test_product.py`、`tools/build-ios.sh product simulator`）与样本计数器（`ResearchCounter` UI 测试）的源码不改动，测试和构建继续通过。
- **AC-06 独立编译**：`xcodebuild build -project apps/ReplyWorkbench/ReplyWorkbench.xcodeproj -scheme ReplyWorkbench -destination 'platform=iOS Simulator,name=iPhone 16e'` 成功，且没有新增警告。
- **AC-07 单元测试**（`DraftSessionTests`）至少包含：
  1. 每个意图生成确定的非空模板，四个模板互不相同；
  2. `updateDraft` 更新草稿并重置复制状态；
  3. AC-02 列出的空白输入全部拒绝，并断言假写入器调用次数为 0；
  4. 有效草稿复制时，假写入器收到原样文本（含首尾空格）；重复复制写入次数递增、状态保持 `.copied`；
  5. F03 迁移：未编辑时切换直接替换；编辑后切换返回 `.needsConfirmation`，取消后不变，确认后替换；空白草稿切换直接替换；再次选择当前意图且未编辑时返回 `.unchanged`。
- **AC-08 UI 主路径**（`ReplyWorkbenchUITests.testMainPath`）：启动后看到 `emptyStateHint`，`copyDraft` 不可用 → 点 `intent.soften` → `draftEditor` 非空，`copyDraft` 可用 → 在编辑器末尾输入文字 → 点 `copyDraft` → `copyStatus` 显示「已复制到剪贴板」→ 点 `intent.decline` → 出现确认框，点「保留当前草稿」→ 编辑器仍含刚输入的文字。UI 测试**不读取**系统剪贴板，避免触发粘贴授权提示；剪贴板内容由 AC-07 第 4 项验证。各步骤截图作为附件。
- **AC-09 交付隔离**：公开 PR 只包含 `apps/ReplyWorkbench/`、`docs/原创/`，以及必要的 CI、检查脚本和 README 增补。不含第三方文案、素材、证据原件、私人路径或 Agent 日志。
