## 2. 实际实现说明（以已复核代码为准）

全部实现严格落实 [回应练习台-键盘扩展切片架构.md](回应练习台-键盘扩展切片架构.md) 中的核心决定 `K01–K07` 与架构复核修订 `R1–R11`：

### 2.1 领域核心层（`apps/ReplyWorkbench/Core/`，仅导入 `Foundation`）

- **`TextInserting`（`Core/TextInserting.swift`）**：标记 `@MainActor` 的引用类型协议，仅定义 `insertText(_:)` 与 `deleteBackward()` 两个写入接口，用于解耦系统 `UITextDocumentProxy` 与主应用内存预览适配器（`R4`）。
- **`KeyboardPanelState` 与 `InsertStatus`（`Core/KeyboardPanelState.swift`）**：
  - 默认状态为 `selectedIntent = .decline`、`status = .idle`，直接复用首发切片既有 `ReplyIntent`（婉拒、缓和、确认、跟进）与 `ReplyTemplates.text(for:)`。
  - `showsPlaceholderHint` 仅在 `selectedIntent == .confirm` 时返回 `true`。
  - `select(_:)` 切换意图并将 `status` 复位为 `.idle`。
  - `insert(into:)`、`insertNewline(into:)` 与 `deleteBackward(in:)` 均标 `@MainActor`：`insert` 每次均将完整模板文本写入目标并置状态为 `.inserted`（连续点击不做去重）；`insertNewline` 写入 `"\n"` 且保持 `status` 不变；`deleteBackward` 转发一次退格且保持 `status` 不变。

### 2.2 共用面板视图（`apps/ReplyWorkbench/KeyboardUI/KeyboardPanelView.swift`）

- 同时编译进主应用 `ReplyWorkbench` 与键盘扩展 `ReplyWorkbenchKeyboard` 两个 Target（`K05`），通过泛型插槽 `leadingAccessory` 隔离扩展专用切换键，保持 `KeyboardUI` 不依赖任何扩展 API（`R5`）。
- 布局自上而下依次为：
  1. **意图条**：4 个等分按钮（`keyboard.intent.decline` / `soften` / `confirm` / `followUp`），选中项采用 `.borderedProminent` 并附加 `.isSelected` 可访问性 trait。
  2. **预览区**：只读 `Text`（`keyboard.preview`），字体 `.callout`、最多 3 行（`lineLimit(3)`），视觉截断但点击「插入」时写入完整模板；`.confirm` 时额外显示 footnote「插入后请在输入框中补全括号内容」。
  3. **操作行**：左侧放置 `leadingAccessory`，依次为「插入」（`keyboard.insert`）、「⌫」（`keyboard.delete`，辅助标签「退格」）与「换行」（`keyboard.newline`）。
  4. **状态行**：固定一行占位（`keyboard.status`），不使用浮层或 Toast；`.inserted` 时显示「已插入」，`.idle` 时隐藏辅助播报。
- 整体施加 `.dynamicTypeSize(...DynamicTypeSize.xxLarge)`，确保 260pt 扩展面板在高辅助字号下保持可读且按钮不被截断（`R6`）。

### 2.3 键盘扩展与工程隔离（`apps/ReplyWorkbench/Keyboard/` 与 `project.pbxproj`）

- **扩展配置（`Keyboard/Info.plist`）**：声明 `NSExtensionPointIdentifier = com.apple.keyboard-service`、`NSExtensionPrincipalClass = $(PRODUCT_MODULE_NAME).KeyboardViewController`、`RequestsOpenAccess = false`、`PrimaryLanguage = zh-Hans`、`IsASCIICapable = false`、`PrefersRightToLeft = false`（`K02`）。
- **文本代理唯一出口（`Keyboard/ProxyTextInserter.swift`）**：全仓唯一允许出现 `textDocumentProxy` 的文件（`R1`），标记 `@MainActor` 并弱引用 `UIInputViewController`，仅转发 `insertText(_:)` 与 `deleteBackward()`，不读取任何宿主输入上下文。
- **切换键盘桥接（`Keyboard/InputModeSwitchKey.swift`）**：以 `UIViewRepresentable` 封装系统 `UIButton`（`globe` 图标、辅助标签「切换键盘」），弱引用控制器并向 `#selector(UIInputViewController.handleInputModeList(from:with:))` 绑定 `.allTouchEvents`（`R5`）。
- **键盘控制器（`Keyboard/KeyboardViewController.swift`）**：
  - `viewDidLoad` 通过 `UIHostingController` 承载根视图并固定高度约束 `260pt`（priority `999`）。
  - `viewWillAppear` 重新创建含新 `UUID` 标识的根视图，通过 `.id(identity)` 强制重建 `KeyboardPanelState()`，不持久化跨会话状态（`K07`）。
  - 按系统属性 `needsInputModeSwitchKey` 条件传入 `InputModeSwitchKey`（`44×44pt`），为 `false` 时不展示切换键。
  - 不覆写 `textWillChange` / `textDidChange`，不读取任何宿主文本。
- **Target 隔离与嵌入（`K01` / `K04` / `R9`）**：
  - `ReplyWorkbenchKeyboard` Target 仅编译 `ReplyIntent.swift`、`ReplyTemplates.swift`、`KeyboardPanelState.swift`、`TextInserting.swift`、`KeyboardPanelView.swift` 及 `Keyboard/` 下 3 个 Swift 文件，**不编入** `App/`、`DraftSession.swift`、`ClipboardWriting.swift`，无 Frameworks 链接阶段。
  - 构建设置配置 `IPHONEOS_DEPLOYMENT_TARGET = 17.0`、`SWIFT_VERSION = 5.0`、`APPLICATION_EXTENSION_API_ONLY = YES`、`SKIP_INSTALL = YES`、`CODE_SIGN_STYLE = Automatic`、`INFOPLIST_KEY_CFBundleDisplayName = "回应练习台"`、`MARKETING_VERSION = 1.0`、`CURRENT_PROJECT_VERSION = 1`，不设 `DEVELOPMENT_TEAM` 与 `CODE_SIGN_ENTITLEMENTS`。
  - 主应用新增 Embed Foundation Extensions 构建阶段将 `ReplyWorkbenchKeyboard.appex` 嵌入 `PlugIns/`；共享 Scheme `ReplyWorkbench` 的 Build 列表同时包含主应用与键盘扩展。

### 2.4 主应用集成（`apps/ReplyWorkbench/App/`）

- **`PreviewTextInserter`（`App/PreviewTextInserter.swift`）**：`@MainActor` 内存写入器，遵循 `ObservableObject` 与 `TextInserting`；`insertText` 追加文本，`deleteBackward` 在非空时调用 `text.removeLast()` 按 Swift `Character`（Extended Grapheme Cluster）删除一个字形簇，并提供 `clear()` 清空预览。
- **`WorkbenchView`（`App/WorkbenchView.swift`）**：
  - 既有首屏布局（标题、意图网格、草稿区、一次性撤销模板替换、复制草稿与状态行）与原有可访问性标识全部保持不变（`K06`）。
  - 在 `copySection` 下方追加「在其他 App 中使用」区块：
    - 启用步骤说明（`keyboardSetupSteps`）：「设置 → 通用 → 键盘 → 键盘 → 添加新键盘 → 回应练习台。无需开启完全访问。」
    - 「打开设置」按钮（`openSettings`）：固定调用 `UIApplication.shared.open(URL(string: UIApplication.openSettingsURLString)!)`，不使用 `@Environment(\.openURL)`（`R2`）。
    - 「键盘预览」子区：嵌入共用 `KeyboardPanelView`（`leadingAccessory: EmptyView()`），下方以 `keyboardPreviewOutput` 展示预览输出（`accessibilityElement(children: .ignore)`、`accessibilityLabel("键盘预览输出")`、`accessibilityValue(previewInserter.text)`，空时视觉显示「尚未插入」而 `value` 为空串，`R7`），附「清空预览」按钮（`clearKeyboardPreview`）。
