## 2. 交互设计

### 2.1 扩展面板（固定高度 260pt，自上而下）

0. **字号上限**：`KeyboardPanelView` 整体施加 `.dynamicTypeSize(...DynamicTypeSize.xxLarge)`。260pt 固定高度装不下辅助功能字号下的四行预览加两行按钮；系统键盘同样不随辅助字号无限放大。主应用的其他区块不受此上限影响。
1. **意图条**：四个按钮横向等分，文字取 `ReplyIntent.title`，选中项 `.borderedProminent` 并带 `.isSelected` trait。
2. **预览区**：显示当前意图模板，`.font(.callout)`，最多 3 行，超出截断（`lineLimit(3)`），只读。截断只影响显示，插入的始终是完整模板。
3. **操作行**：
   - 左侧「🌐」切换键盘，仅在 `needsInputModeSwitchKey == true` 时显示。实现为 `Keyboard/InputModeSwitchKey.swift` 中的 `UIViewRepresentable`：`UIButton` 以 `addTarget(controller, action: #selector(UIInputViewController.handleInputModeList(from:with:)), for: .allTouchEvents)` 绑定（`controller` 为 `weak`）。`KeyboardPanelView` 只提供一个 `leadingAccessory` 插槽，不依赖 `UIInputViewController`；主应用预览传入 `EmptyView`。
   - 「插入」主按钮：调用一次 `insertText(模板)`，状态行显示「已插入」。连续点按会再次插入，符合用户显式意图，不做去重。
   - 「⌫」退格：调用 `deleteBackward()` 一次。
   - 「换行」：插入 `"\n"`。
4. **状态行**：固定一行，`idle` 为空，插入后为「已插入」，切换意图后回到空。不用浮层。

`.confirm` 模板含【时间】等占位符，原样插入，由用户在宿主中改写；预览区下方用 footnote 提示「插入后请在输入框中补全括号内容」，仅对 `.confirm` 显示。

### 2.2 主应用「键盘」区块（位于复制按钮与状态行之下）

- 标题「在其他 App 中使用」。
- 步骤文字：设置 → 通用 → 键盘 → 键盘 → 添加新键盘 → 回应练习台。明确写「无需开启完全访问」。
- 按钮「打开设置」：`UIApplication.shared.open(URL(string: UIApplication.openSettingsURLString)!)`。不使用 SwiftUI `@Environment(\.openURL)`，因为 §5 第 4 条在全目录拒绝 `openURL` 词法。`UIApplication` 与 `openSettingsURLString` 只允许出现在 `App/`。
- 「键盘预览」：嵌入 `KeyboardPanelView`（不固定高度），插入目标为 `PreviewTextInserter`，下方显示其 `text`（不可编辑、不复制、不持久化），旁边「清空预览」。
- 输出元素 `keyboardPreviewOutput`：容器 `.accessibilityElement(children: .ignore)`，`accessibilityLabel("键盘预览输出")`，`accessibilityValue(text)`；空串时视觉上显示次要色「尚未插入」，但 value 为空串。UI 测试读 `value` 判定，不读 label，避免空 `Text` 在可访问性树中消失。
- 区块追加在 `copySection` 之后，同一个 `ScrollView` 内，不插入到首屏意图与草稿之间。

### 2.3 可访问性标识（新增，固定）

扩展与预览共用：`keyboard.intent.decline`、`keyboard.intent.soften`、`keyboard.intent.confirm`、`keyboard.intent.followUp`、`keyboard.preview`、`keyboard.insert`、`keyboard.delete`、`keyboard.newline`、`keyboard.status`。主应用独有：`keyboardSetupSteps`、`openSettings`、`keyboardPreviewOutput`、`clearKeyboardPreview`。既有标识不改名。

## 3. 领域模型（`Core/`，只导入 Foundation）

```swift
@MainActor
protocol TextInserting: AnyObject {
    func insertText(_ text: String)
    func deleteBackward()
}

enum InsertStatus: Equatable { case idle, inserted }

struct KeyboardPanelState: Equatable {
    private(set) var selectedIntent: ReplyIntent = .decline
    private(set) var status: InsertStatus = .idle
    var previewText: String { ReplyTemplates.text(for: selectedIntent) }
    var showsPlaceholderHint: Bool { selectedIntent == .confirm }

    mutating func select(_ intent: ReplyIntent)                     // 更新意图，status 回到 .idle
    @MainActor mutating func insert(into target: TextInserting)     // insertText(previewText)，status = .inserted
    @MainActor mutating func insertNewline(into target: TextInserting)  // insertText("\n")，status 不变
    @MainActor func deleteBackward(in target: TextInserting)        // 调用一次 deleteBackward()，status 不变
}
```

- `TextInserting` 标为 `@MainActor`：两个实现（`UIInputViewController` 转发者与 `ObservableObject` 预览）都在主线程，标注后 Swift 6 严格并发下也无隔离冲突。`@MainActor` 来自标准库，`Core/` 仍只导入 Foundation。单测类相应标 `@MainActor`。

- `Keyboard/ProxyTextInserter.swift`：`@MainActor final class`，持有 `weak var controller: UIInputViewController?`，经 `controller?.textDocumentProxy` 转发两个方法。仓库中只有该文件允许出现 `textDocumentProxy`；`KeyboardViewController` 只把 `self` 交给 inserter，`needsInputModeSwitchKey` 是控制器自身属性，不经 proxy。
- `App/PreviewTextInserter.swift`：`@MainActor final class ... ObservableObject`，`@Published private(set) var text`，`insertText` 追加，`deleteBackward` 删除最后一个 `Character`（字形簇），空串时无操作。
- `KeyboardPanelView` 接收 `Binding<KeyboardPanelState>` 与 `TextInserting`，不关心目标是系统还是预览。

## 5. 静态检查（扩展 `apps/ReplyWorkbench/check.sh`）

新增规则，均用 grep / plutil，CI 和本机都能运行：

1. 现有 `UIPasteboard` 扫描范围加入 `Keyboard KeyboardUI`，结果仍须只有 `SystemClipboardWriter.swift` 一行。
2. 现有禁用 API 规则扫描范围加入 `Keyboard KeyboardUI`。
3. `grep -RlF textDocumentProxy App Core KeyboardUI Keyboard Tests UITests` 的输出必须恰好为 `Keyboard/ProxyTextInserter.swift` 一行。
4. 全目录（`App Core KeyboardUI Keyboard Tests UITests`）拒绝 `documentContextBeforeInput|documentContextAfterInput|selectedText|hasText|documentIdentifier|openURL|extensionContext`。`Core KeyboardUI Keyboard` 另拒绝 `UIApplication|openSettingsURLString|UIPasteboard`。即 `UIApplication`、`openSettingsURLString` 只能出现在 `App/`。
5. `Keyboard/Info.plist`：`plutil -extract NSExtension.NSExtensionAttributes.RequestsOpenAccess raw` 必须为 `false`，`NSExtensionPointIdentifier` 必须为 `com.apple.keyboard-service`。macOS 以外缺少 plutil 时用 grep 等价判断。
6. 继续禁止 `.entitlements`、`CODE_SIGN_ENTITLEMENTS`、`NS*UsageDescription`。

所有扫描对目录缺失按失败处理（`grep` 返回 2 时 `reject_matches` 已退出 1），避免目录改名后检查静默通过。

## 10. Claude 架构复核修订（新会话）

复核依据：本文初稿、Gemini 核对意见、现有 `apps/ReplyWorkbench/`（`check.sh`、`WorkbenchView.swift`、`testMainPath`、工程设置）与 Xcode 26.2 本机环境。只修正缺陷与平台事实错误，K01–K07 的产品方向不变。

| 编号 | 问题 | 修订 | 理由 |
|---|---|---|---|
| R1 | §3 与 §5 第 3 条对 `textDocumentProxy` 白名单口径冲突；`needsInputModeSwitchKey` 不是 proxy 属性 | 收紧为仅 `ProxyTextInserter.swift`，并用「输出恰好一行」判定 | 控制器只需交出 `self`，放宽白名单会让控制器可以读 proxy 上下文而检查不报警 |
| R2 | 主应用「打开设置」若用 `@Environment(\.openURL)` 会被全目录 `openURL` 规则拦截；扩展侧未禁止 `UIApplication` | 主应用固定用 `UIApplication.shared.open`；`Core KeyboardUI Keyboard` 禁 `UIApplication`、`openSettingsURLString`、`UIPasteboard`；`extensionContext` 整词禁用 | 保持全目录 `openURL` 禁令不变，同时堵住共享 UI 的跳转与剪贴板路径 |
| R3 | 宿主上下文禁用表遗漏 `hasText`、`documentIdentifier` | 加入 §5 第 4 条与 K03 | 二者同样暴露宿主输入框状态，本切片不需要 |
| R4 | `@MainActor` 的 `PreviewTextInserter` 遵循非隔离协议，Swift 6 严格并发下为错误 | `TextInserting` 与写入方法标 `@MainActor` | 两个实现都在主线程，标注不增加运行成本 |
