## 2. 交互设计

### 2.1 扩展面板（固定高度 260pt，自上而下）

1. **意图条**：四个按钮横向等分，文字取 `ReplyIntent.title`，选中项 `.borderedProminent` 并带 `.isSelected` trait。
2. **预览区**：显示当前意图模板，最多 4 行，超出截断（`lineLimit(4)`），只读。
3. **操作行**：
   - 左侧「🌐」切换键盘，仅在 `needsInputModeSwitchKey == true` 时显示，调用 `handleInputModeList(from:with:)`（UIKit 按钮，经桥接放入 SwiftUI 布局）。
   - 「插入」主按钮：调用一次 `insertText(模板)`，状态行显示「已插入」。连续点按会再次插入，符合用户显式意图，不做去重。
   - 「⌫」退格：调用 `deleteBackward()` 一次。
   - 「换行」：插入 `"\n"`。
4. **状态行**：固定一行，`idle` 为空，插入后为「已插入」，切换意图后回到空。不用浮层。

`.confirm` 模板含【时间】等占位符，原样插入，由用户在宿主中改写；预览区下方用 footnote 提示「插入后请在输入框中补全括号内容」，仅对 `.confirm` 显示。

### 2.2 主应用「键盘」区块（位于复制按钮与状态行之下）

- 标题「在其他 App 中使用」。
- 步骤文字：设置 → 通用 → 键盘 → 键盘 → 添加新键盘 → 回应练习台。明确写「无需开启完全访问」。
- 按钮「打开设置」：`UIApplication.openSettingsURLString`。此调用只在 `App/` 允许出现。
- 「键盘预览」：嵌入 `KeyboardPanelView`，插入目标为预览专用的内存文本 `previewText`，下方 `Text` 显示其内容（不可编辑、不复制、不持久化），旁边「清空预览」。

### 2.3 可访问性标识（新增，固定）

扩展与预览共用：`keyboard.intent.decline`、`keyboard.intent.soften`、`keyboard.intent.confirm`、`keyboard.intent.followUp`、`keyboard.preview`、`keyboard.insert`、`keyboard.delete`、`keyboard.newline`、`keyboard.status`。主应用独有：`keyboardSetupSteps`、`openSettings`、`keyboardPreviewOutput`、`clearKeyboardPreview`。既有标识不改名。

## 3. 领域模型（`Core/`，只导入 Foundation）

```swift
protocol TextInserting: AnyObject {
    func insertText(_ text: String)
    func deleteBackward()
}

enum InsertStatus: Equatable { case idle, inserted }

struct KeyboardPanelState: Equatable {
    private(set) var selectedIntent: ReplyIntent = .decline
    private(set) var status: InsertStatus = .idle
    var previewText: String { ReplyTemplates.text(for: selectedIntent) }
    var showsPlaceholderHint: Bool { selectedIntent == .confirm }

    mutating func select(_ intent: ReplyIntent)          // 更新意图，status 回到 .idle
    mutating func insert(into target: TextInserting)     // insertText(previewText)，status = .inserted
    mutating func insertNewline(into target: TextInserting)  // insertText("\n")，status 不变
    func deleteBackward(in target: TextInserting)        // 调用一次 deleteBackward()
}
```

- `Keyboard/ProxyTextInserter.swift`：`final class` 持有 `weak` 的 `UITextDocumentProxy` 所属控制器，转发两个方法。仓库中只有该文件允许出现 `textDocumentProxy`。
- `App/PreviewTextInserter.swift`：`@MainActor final class ... ObservableObject`，`@Published private(set) var text`，`insertText` 追加，`deleteBackward` 删除最后一个 `Character`（字形簇），空串时无操作。
- `KeyboardPanelView` 接收 `Binding<KeyboardPanelState>` 与 `TextInserting`，不关心目标是系统还是预览。

## 5. 静态检查（扩展 `apps/ReplyWorkbench/check.sh`）

新增规则，均用 grep / plutil，CI 和本机都能运行：

1. 现有 `UIPasteboard` 扫描范围加入 `Keyboard KeyboardUI`，结果仍须只有 `SystemClipboardWriter.swift` 一行。
2. 现有禁用 API 规则扫描范围加入 `Keyboard KeyboardUI`。
3. `textDocumentProxy` 只允许出现在 `Keyboard/ProxyTextInserter.swift` 与 `Keyboard/KeyboardViewController.swift`（后者仅用于把 proxy 交给 inserter 和读取 `needsInputModeSwitchKey`）。
4. 全目录拒绝 `documentContextBeforeInput|documentContextAfterInput|selectedText|openURL|extensionContext\?\.open`；`openSettingsURLString` 只允许出现在 `App/`。
5. `Keyboard/Info.plist`：`plutil -extract NSExtension.NSExtensionAttributes.RequestsOpenAccess raw` 必须为 `false`，`NSExtensionPointIdentifier` 必须为 `com.apple.keyboard-service`。macOS 以外缺少 plutil 时用 grep 等价判断。
6. 继续禁止 `.entitlements`、`CODE_SIGN_ENTITLEMENTS`、`NS*UsageDescription`。

## 6. 验收条件

- **KC-01 单测** `KeyboardPanelStateTests`（使用记录型假 inserter）：默认意图为 `.decline` 且预览等于模板；`select` 更新预览并把状态复位为 `.idle`；`insert` 恰好写入一次且字节与 `ReplyTemplates.text(for:)` 一致，状态为 `.inserted`；连续两次插入写入两次；`insertNewline` 写入 `"\n"`；`deleteBackward` 调用一次；只有 `.confirm` 显示占位提示。
- **KC-02 预览删除**：`PreviewTextInserter` 对 `"e\u{301}👩‍💻"` 退格一次后剩 `"e\u{301}"`，空串退格无操作（单测）。
- **KC-03 UI 测试** `testKeyboardPreview`：滚动到 `keyboard.insert`，点 `keyboard.intent.soften` → 点 `keyboard.insert` → `keyboardPreviewOutput` 等于缓和模板、`keyboard.status` 为「已插入」→ 点 `keyboard.newline` 再点 `keyboard.delete` → 输出仍等于模板 → 点 `clearKeyboardPreview` → 输出为空。既有 `testMainPath` 及撤销路径继续通过。
- **KC-04 产物检查**（CI）：模拟器构建后 `ReplyWorkbench.app/PlugIns/ReplyWorkbenchKeyboard.appex` 存在，其 `Info.plist` 中 `RequestsOpenAccess` 为 `false`、扩展点正确；`codesign -d --entitlements :-` 对 `.appex` 的输出不含 `com.apple.security.application-groups`。
- **KC-05 最小权限**：§5 全部规则通过；`bash tools/check.sh` 通过。
- **KC-06 既有资产**：节奏记录、样本计数器、回应练习台既有测试与 CI 步骤不改语义。
- **KC-07 交付隔离**：只修改 `apps/ReplyWorkbench/`、`docs/原创/`、必要的 CI 与 README 一行。
